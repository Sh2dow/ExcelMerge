# ExcelMerge 用户指南

项目地址：[https://github.com/ksgfk/ExcelMerge](https://github.com/ksgfk/ExcelMerge)。

ExcelMerge 用于比较和三方合并表格文件，支持 `.xlsx`、`.csv` 和 `.tsv`。它不需要安装 Microsoft Excel。

## 准备环境

需要安装 .NET 10 SDK。项目根目录执行以下命令可以构建整个解决方案：

    dotnet build ExcelMerge.slnx --configuration Release

运行桌面程序：

    dotnet run --project src/ExcelMerge.Desktop/ExcelMerge.Desktop.csproj

使用源码运行桌面程序时，也可以把两个文件拖入窗口进行比较，把三个文件拖入窗口进行三方合并。使用发布包时，直接运行包内 bin/ExcelMerge.Desktop.exe；发布包已经包含自包含运行时，不需要额外安装 .NET Runtime。

## 比较两个文件

1. 在顶部选择“比较”。
2. 在“本地”和“远端”输入框中选择文件，或直接拖入两个文件。
3. 点击“运行”。
4. 在左侧选择工作表，在中间的同步网格中查看两侧内容和变化。

比较结果支持：

- 按工作表查看变化；
- 只显示发生变化的行；
- 在搜索框中搜索单元格内容；
- 使用完全匹配、区分大小写和正则表达式选项；
- 使用“上一个”“下一个”在变化之间跳转；
- 点击单元格后，在检查器中查看地址、公式、类型和值；
- 复制选中的内容为 TSV 或 CSV。

“本地”和“远端”只是比较结果中的两侧名称，不代表文件一定来自 Git。需要交换两侧时，可以点击“交换两侧”。

## 三方合并

三方合并需要三个文件：

- **基准**：两边分支共同的基础版本，也就是 BASE；
- **本地**：当前分支版本，也就是 LOCAL；
- **远端**：要合入的分支版本，也就是 REMOTE。

操作步骤：

1. 在顶部选择“合并”。
2. 分别选择基准、本地和远端文件。
3. 点击“运行”，等待工作表加载完成。
4. 在左侧“冲突”列表中逐项选择冲突。
5. 查看检查器中的基准、本地和远端值，根据实际意图选择“使用本地”“使用远端”“保留两者”或“使用自定义”。
6. 确认冲突数为零后，点击“保存结果”，选择输出文件。

只在一侧发生的修改通常会自动合并；两侧修改相同的内容也不会产生冲突。两侧对同一个单元格、行、工作表或工作表元数据作出不兼容修改时，需要手动解决。只要还有未解决冲突，就不能保存结果。

“保留两者”是行级决策，用于同时保留本地行和远端行；它不是普通单元格的第三个取值。自定义值只适用于界面允许编辑的单元格级冲突。

## 比较设置

点击“设置”可以调整语言、主题、网格显示和比较规则。

- **关键列**：用列字母或正整数填写，例如 `A`、`C` 或 `1,3`。关键列有助于在插入、删除或移动行后识别同一条记录。
- **比较公式缓存值**：除公式文本外，比较公式保存的缓存结果。
- **比较显示文本**：比较文件适配器提供的显示文本。
- **比较单元格样式**：把单元格样式变化计入差异。
- **比较行元数据**：把行高、隐藏等行元数据变化计入差异。
- **将显式空白视为缺失**：把没有样式的显式空白单元格与不存在的稀疏单元格视为相同。

公式比较的是文件中保存的公式文本和缓存值，ExcelMerge 不会重新计算公式。调整比较规则后重新点击“运行”即可重新生成结果。

## 文件格式和输出

| 格式 | 说明 |
| --- | --- |
| `.xlsx` | 支持标准、未加密的 Open XML 工作簿；合并输出以本地文件的包结构和样式为基础。 |
| `.csv` | 作为名为 `Data` 的单一工作表处理；所有字段保持文本。输出为 UTF-8、无 BOM、CRLF 换行。 |
| `.tsv` | 与 CSV 使用相同的单一工作表模型，字段分隔符为制表符。 |

同一次比较或合并中的文件必须使用相同格式，合并输出也必须使用相同扩展名。旧版 `.xls` 不受支持，请先在 Excel 或其他工具中转换为 `.xlsx`。加密、损坏的工作簿以及部分不支持的 Open XML 变换会被拒绝。

保存时，程序会重新检查源文件指纹和可用磁盘空间，在目标目录创建事务文件，并在校验通过后替换目标文件。源文件在操作期间被其他程序修改时，保存会失败，以避免覆盖基于旧内容生成的结果。

## 命令行

比较两个文件：

    dotnet run --project src/ExcelMerge.Cli/ExcelMerge.Cli.csproj -- diff LOCAL REMOTE

自动合并三个文件并输出结果：

    dotnet run --project src/ExcelMerge.Cli/ExcelMerge.Cli.csproj -- merge BASE LOCAL REMOTE --output RESULT

命令行合并只适用于没有未解决冲突的情况；需要人工选择时，请使用桌面程序。退出码含义如下：

| 退出码 | 含义 |
| --- | --- |
| `0` | 比较无差异、合并成功、帮助或版本输出。 |
| `1` | 存在差异、存在未解决冲突、操作取消或操作失败。 |
| `2` | 命令行用法错误。 |

## 与 Git 配合使用

ExcelMerge 的 CLI 提供 Git merge driver。配置分为两部分：

1. 在项目的 `.gitattributes` 中声明哪些文件使用 ExcelMerge。该文件应提交到仓库：

       *.xlsx merge=excelmerge
       *.csv  merge=excelmerge
       *.tsv  merge=excelmerge

2. 在每台开发机上配置已发布的 CLI 路径。建议使用稳定的发布目录，而不是临时构建目录：

       git config --local merge.excelmerge.name "ExcelMerge 三方工作簿合并"
       git config --local merge.excelmerge.driver '"C:/Tools/ExcelMerge/ExcelMerge.Cli.exe" merge-driver %O %A %B %L %P'

配置完成后，可以检查：

    git config --get merge.excelmerge.driver
    git check-attr merge -- report.xlsx

Git 自动合并时，ExcelMerge 会把 BASE、LOCAL、REMOTE 复制到临时目录，成功生成结果后再替换当前文件。发生冲突或程序失败时，不会提交不完整的结果，Git 会保留未合并状态。

## Git 冲突处理

当 `git merge` 报告冲突时：

1. 不要立即执行 `git add`。
2. 用 `git status` 找到冲突文件，并保留 Git 的三个版本：BASE、LOCAL、REMOTE。
3. 在桌面程序中进入“合并”，分别打开这三个版本。
4. 逐项解决“冲突”列表，直到没有未解决冲突。
5. 将结果保存到冲突文件的路径。
6. 用 `git add -- <文件>` 标记已解决，再继续提交或执行后续合并流程。

如果直接选择“使用本地”或“使用远端”，会放弃另一侧对该文件的全部修改；需要同时保留两边内容时，应使用 ExcelMerge 的三方合并结果，而不是简单地执行 `git checkout --ours` 或 `git checkout --theirs`。

## 常见问题

**为什么 `.xls` 打不开？**

ExcelMerge 只支持 `.xlsx`、`.csv` 和 `.tsv`。请先将 `.xls` 转换为 `.xlsx`。

**为什么有差异时 CLI 返回 1？**

`diff` 命令用退出码表示结果，不输出文本报告。返回 `1` 可能表示有差异，也可能表示操作失败；需要同时查看标准错误输出。

**为什么自动合并没有生成文件？**

最常见原因是存在未解决冲突、三份文件格式不同、源文件在保存期间发生变化，或者工作簿包含不支持的变换。查看桌面程序的“诊断”窗口或 CLI 的错误输出，然后改用桌面程序逐项解决冲突。

**能否让 ExcelMerge 重新计算公式？**

不能。程序比较公式文本和可选的缓存值，但不会充当 Excel 计算引擎。保存后如需刷新公式结果，请使用支持公式计算的电子表格软件打开文件。
